Dataset proposal status

Pending instructor review. We propose using MSR-VTT-10K for text-to-video retrieval, with video-only and text-only retrieval diagnostics as the proposed unimodal baselines.

This M1 proposal uses published dataset statistics and a planned experiment protocol. We request confirmation that the two diagnostics satisfy the unimodal baseline requirement. Main experiments will begin after the instructor records Approved or Approved with conditions.

Problem statement

Given an English caption, rank a gallery of video clips by relevance. The study tests whether caption-conditioned frame weighting improves retrieval over averaging sampled frames, especially when the described action is brief.

  • Task: text-to-video retrieval.
  • Input: an English caption query and a gallery of clips represented by sampled RGB frames.
  • Output: ranked clip IDs, scored against the annotated clip ID for the query.
  • Alignment: human annotators watched each clip before captioning it. The annotations link each caption to its clip through video_id.
  • Challenges: generic captions, similar clips, brief actions, scene changes and captions whose details may depend on audio.

Dataset description and preliminary EDA

  • Name and source: Microsoft Research MSR-VTT-10K, published by Xu et al. at CVPR 2016.
  • Version: original 10,000-clip release and its published train, validation and test protocol.
  • Download: MSRVTT_Videos.zip (2.19 GB) and JSON annotations from the Hugging Face mirror. Verify the mirror files against the original split before use.
  • Usage terms: the mirror does not state a dataset license. The original media and annotation terms still need to be documented for review. Link to the source rather than redistributing clips with project artifacts.
  • Annotations: English captions, clip IDs and broad categories. Use source URLs and clip timestamps, where available, to audit grouping and provenance.

Published population: the original release reports 10,000 clips and 200,000 clip–caption pairs. The counts below describe the original release. Retained counts will be measured from the files used for the experiments.

Pair validation and preprocessing plan

  1. Match each annotation's video_id to its MP4 file and retain source identifiers for auditing.
  2. Check for missing or unreadable videos, empty captions and duplicate records. Manually review 100 pairs sampled across splits and categories with seed 42. Log confirmed mismatches and report the counts before and after filtering.
  3. Sample eight uniformly spaced RGB frames per clip and apply the pretrained image encoder's 224 × 224 preprocessing. Tokenize captions with the text encoder's tokenizer and report truncation rates.
  4. Use sampled frames and captions as model inputs. Keep clip and source IDs, filenames and category labels for alignment, scoring and auditing.

Splitting and leakage prevention

Split unit: original source video. Group clips by source-video ID where available and keep all captions for a clip together. Audit the original release split for shared sources and duplicates before training.

  • Training / validation / test: use the original 6,513 / 497 / 2,990 clip protocol. The mirror's separate 1,000-clip retrieval benchmark uses a different split.
  • Leakage checks: check clip IDs, source IDs and exact duplicates across splits. If overlap is found, remove the overlapping groups from training and, where they overlap test, from validation. Document the change and retained counts.
  • Test protocol: tune on validation clips. For final scoring, rank the full retained test gallery for each retained test caption and score the rank of its annotated clip.

Evaluation and model plan

  • Primary metric: Recall@1, the percentage of query captions whose annotated clip ranks first.
  • Secondary metrics: Recall@5, Recall@10 and median rank. Include a random-ranking reference on the same test gallery.
  • Reporting: use the same query set and gallery for both multimodal models. Report mean and standard deviation over seeds 42, 43 and 44. The unimodal diagnostics use different query types, so their recall values answer different questions.
  • Training plan: freeze the encoders and cache their features. Train the retrieval heads with contrastive cross-entropy on matched pairs and in-batch negatives. Sample one pair per clip in each batch to avoid treating alternate captions for the same clip as negatives. Select checkpoints by validation Recall@1 on the corresponding task.

For the ablation, replace learned frame weights with uniform weights and retrain the same scoring head. Compare the multimodal models with matched inputs and training budgets. Inspect examples where the frames and captions agree or conflict, and report errors involving brief actions, ambiguous captions and visually similar clips.

Compute and storage estimate

Planned hardware is an NVIDIA GTX 1660 SUPER with 6 GB VRAM. Extract frozen features one encoder at a time and score the test gallery in batches. Caching 80,000 frame embeddings and 200,000 caption embeddings in float32 requires about 0.47 GB. Allow approximately 10 GB of working disk space plus the Python environment.

Budget 4–12 hours provisionally for decoding, feature extraction, head training and evaluation. Calibrate with 500 training clips after approval, then report wall time, peak GPU memory and retrieval latency for the main configurations.

Subset rules

Use all eligible clips and captions by default. If the pilot shows that a smaller training set is needed, request approval for a source-grouped training subset selected with seed 42 and approximately stratified by category. Keep the validation and test sets fixed for model comparisons, and publish the retained counts.
