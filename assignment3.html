Dataset proposal status

Pending instructor review. We propose using PairDX version 1.0 for six-class image–text classification. The archive contains a larger, imbalanced population than the published description; approval is requested for the archive population described below.

This M1 submission contains preliminary metadata analysis and a proposed experiment plan. Main experiments will begin after the instructor records Approved or Approved with conditions.

Problem statement

Predict the broad type of a medical figure from its image and original caption. The study asks whether combining visual and textual evidence improves classification over either modality alone, especially when captions are short or ambiguous.

  • Task: six-class image–text classification.
  • Input: one WEBP image and its original English caption.
  • Output: one of radiology, medical photograph, endoscopy, chart, ophthalmic imaging or electrography, using image_type as the target.
  • Alignment: each metadata record associates the caption with its image file, original figure and case.
  • Challenges: class imbalance, generic captions, repeated figures/text, multi-panel ambiguity and potentially noisy labels.

Dataset description and preliminary EDA

  • Name and source: PairDX, derived from MultiCaRe.
  • Version: 1.0, published 27 October 2025. DOI: 10.5281/zenodo.17452236.
  • Download: PairDX.zip, approximately 1.93 GB, containing medical images, English captions and image metadata.
  • License: the PairDX record declares MIT, while the archive retains mixed per-image licenses and the upstream collection specifies CC BY-NC-SA with item-specific terms. Preserve attribution and license metadata, check permissions before use, and exclude items with unresolved permissions. Obtain raw images from the original source.
  • Annotations: broad image type, image subtype, machine-learning label lists, a separate semisupervised ground-truth field, and case/figure identifiers. Supplied targets may be noisy and have not been independently verified.

Proposed population: inspection of the ZIP directory and complete metadata found 103,384 WEBP entries and 103,384 metadata records. The public record advertises 22,665 balanced pairs. The proposal uses the supplied archive population, subject to filtering and instructor approval.

Pair validation and preprocessing plan

  1. Read image_metadata.json as newline-delimited JSON. Match file to the archive image basename and rebuild its relative path. Keep case_id and main_image for provenance.
  2. Decode every image, check caption and target availability, and remove invalid pairs. Review 20 randomly selected pairs per class with seed 42, plus short-caption and multi-panel examples. Report missing, noisy and mismatched pairs separately.
  3. Convert images to RGB and use the pretrained image encoder's 224 × 224 preprocessing and normalization. Check that cropping preserves the relevant figure content. Tokenize original captions with the text encoder's tokenizer, with a maximum of 256 wordpieces; report truncation rates.
  4. Use only images and captions as model inputs. Keep filenames, case IDs, label fields and case narratives out of the feature inputs. Fit class weights and any learned preprocessing on training data only.

Splitting and leakage prevention

Split unit: source PMC article. Obtain the article prefix from case_id; all cases, figures and panels from one article stay together. Before splitting, connect article groups sharing exact image duplicates or identical normalized captions of at least eight words, and review near-duplicate image candidates.

  • Training / validation / test: approximately 70% / 15% / 15%, using seed 42 and whole article/duplicate groups.
  • Stratification: preserve class proportions as closely as grouping permits; publish actual retained class and group counts in each split.
  • Leakage checks: verify zero article and duplicate-image overlap. Select settings and checkpoints with validation data; reserve test data for the final fixed comparison.
  • Limitation: cross-article patient identifiers are unavailable, so patient overlap between different articles cannot be ruled out.

Evaluation and model plan

  • Primary metric: macro-F1 across all six classes.
  • Secondary metrics: accuracy, per-class precision/recall/F1 and a confusion matrix.
  • Reporting: compare models on the same fixed split and report mean and standard deviation over run seeds 42, 43 and 44.
  • Training plan: initially freeze both pretrained encoders, cache features, and train classification heads using class-weighted cross-entropy. Select checkpoints by validation macro-F1.

Use identical splits, frozen features and checkpoint rules across models. The proposed gate tests whether adjusting each modality's contribution helps with generic captions or ambiguous figures. Multimodal improvement will be assessed from the results rather than assumed.

Compute and storage estimate

Planned hardware is an NVIDIA GTX 1660 SUPER with 6 GB VRAM. Extract frozen features one encoder at a time, starting with batch size 32. The two float32 feature arrays require approximately 370.5 MB for the candidate population. Allow approximately 10 GB working disk space plus the Python environment.

Reserve approximately 4–12 hours overall: 2–6 GPU-hours for feature extraction, 1–4 hours for classifier experiments and 1–2 hours for evaluation. These are planning estimates; calibrate them with a small training-data pilot after approval.

Subset rules

Use all eligible pairs by default. If measured cost prevents completion, request approval for a training-only cap of 4,000 pairs per class, selected with seed 42 after the group split. Keep validation and test unchanged, use the same training subset for every model, and report retained class/group counts against the course threshold.
